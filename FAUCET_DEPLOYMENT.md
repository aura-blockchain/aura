# AURA Testnet Faucet Deployment Guide

## Overview

The AURA testnet faucet is a production-grade service that distributes test tokens to developers. It features:

- **Rate Limiting**: Per-IP and per-address rate limiting to prevent abuse
- **Database Tracking**: PostgreSQL for request history and analytics
- **Caching**: Redis for high-performance rate limiting
- **Web UI**: Clean, responsive interface for easy token requests
- **REST API**: Programmatic access for automation
- **Health Monitoring**: Built-in health checks and status endpoints
- **Security**: Input validation, SQL injection prevention, optional CAPTCHA

```
     ▼      ▼
┌─────┐  ┌─────┐
│Redis│  │PgSQL│  ← Rate limiting + request tracking
└─────┘  └─────┘
     │
     ▼
┌─────────────────┐
│  Validator-1    │  ← Testnet node (RPC: 26657)
│  (aura-local-4) │
└─────────────────┘
```

## Prerequisites

1. **Testnet Running**: The 4-validator testnet must be running
   ```bash
   docker-compose -f docker-compose.testnet.yml ps
   # Should show: aura-validator-1, aura-validator-2, etc.
   ```

2. **Docker Network**: The `aura_aura-testnet` network must exist
   ```bash
   docker network ls | grep aura-testnet
   ```

3. **aurad Binary**: Built and available in `chain/` directory
   ```bash
   ls chain/aurad
   ```

## Quick Start

### 1. Initialize the Testnet (if not already done)

```bash
# Initialize testnet data
./scripts/testnet-init.sh

# Build Docker image
docker build -t aurad:latest -f docker/Dockerfile.testnet .

# Start testnet
docker-compose -f docker-compose.testnet.yml up -d

# Verify validators are running
docker-compose -f docker-compose.testnet.yml ps
```

### 2. Create and Fund Faucet Wallet

```bash
# Run the faucet setup script
./scripts/faucet-setup.sh
```

This script will:
- Create a new faucet account with a secure mnemonic
- Fund it with 100,000,000 AURA from validator-1
- Generate `.env.faucet` configuration file
- Display the faucet address and balance

## Configuration

### Environment Variables

The faucet is configured via `.env.faucet` (generated by `faucet-setup.sh`):

| Variable | Description | Default | Required |
|----------|-------------|---------|----------|
| `FAUCET_MNEMONIC` | Faucet wallet mnemonic | - | Yes |
| `FAUCET_ADDRESS` | Faucet wallet address | - | Yes |
| `FAUCET_AMOUNT_PER_REQUEST` | Tokens per request (uaura) | 100000000 | No |
| `FAUCET_RATE_LIMIT_IP` | Max requests per IP per window | 20 | No |
| `FAUCET_RATE_LIMIT_ADDR` | Max requests per address per window | 3 | No |
| `FAUCET_RATE_WINDOW` | Rate limit window (hours) | 24 | No |
| `FAUCET_DB_PASSWORD` | PostgreSQL password | auto-generated | No |
| `FAUCET_HCAPTCHA_SECRET` | hCaptcha secret (optional) | - | No |
| `FAUCET_ENVIRONMENT` | Environment mode | development | No |
| `FAUCET_LOG_LEVEL` | Logging level | info | No |

### Customizing Faucet Amount

To change the amount distributed per request:

```bash
# Edit .env.faucet
# Change FAUCET_AMOUNT_PER_REQUEST value
# Values are in micro-AURA (uaura)
# 1 AURA = 1,000,000 uaura

# Examples:
FAUCET_AMOUNT_PER_REQUEST=50000000   # 50 AURA
FAUCET_AMOUNT_PER_REQUEST=100000000  # 100 AURA (default)
FAUCET_AMOUNT_PER_REQUEST=500000000  # 500 AURA

# Restart faucet
docker-compose -f docker-compose.faucet.yml restart faucet-backend
```

### Customizing Rate Limits

```bash
# Edit .env.faucet
# Adjust rate limit values

# Permissive (for development):
FAUCET_RATE_LIMIT_IP=50         # 50 requests per IP
FAUCET_RATE_LIMIT_ADDR=10       # 10 requests per address
FAUCET_RATE_WINDOW=24           # per 24 hours

# Strict (for production):
FAUCET_RATE_LIMIT_IP=10
FAUCET_RATE_LIMIT_ADDR=1
FAUCET_RATE_WINDOW=24

# Restart faucet
docker-compose -f docker-compose.faucet.yml restart faucet-backend
```

## Usage Examples

### Using Web UI

1. Open http://localhost:8081 in browser
2. Enter your AURA address (starts with `aura1`)
3. Click "Request Tokens"
4. Wait for confirmation (usually 6 seconds)
5. Check your balance

### Using curl

```bash
# Request tokens
curl -X POST http://localhost:8081/api/v1/faucet/request \
  -H "Content-Type: application/json" \
  -d '{
    "address": "aura1your_address_here"
  }'

# Check if tokens were received
docker exec aura-validator-1 aurad query bank balances aura1your_address_here \
  --chain-id aura-local-4
```

### Using JavaScript/Node.js

```javascript
const axios = require('axios');

async function requestTokens(address) {
  try {
    const response = await axios.post(
      'http://localhost:8081/api/v1/faucet/request',
      { address }
    );
    console.log('Success:', response.data);
    return response.data.tx_hash;
  } catch (error) {
    console.error('Error:', error.response?.data || error.message);
  }
}

// Usage
requestTokens('aura1your_address_here');
```

### Using Python

```python
import requests

def request_tokens(address):
    url = 'http://localhost:8081/api/v1/faucet/request'
    payload = {'address': address}

    try:
        response = requests.post(url, json=payload)
        response.raise_for_status()
        print('Success:', response.json())
        return response.json()['tx_hash']
    except requests.exceptions.HTTPError as e:
        print('Error:', e.response.json())

# Usage
request_tokens('aura1your_address_here')
```

## Monitoring and Maintenance

### View Logs

```bash
# All services
docker-compose -f docker-compose.faucet.yml logs -f

# Specific service
docker-compose -f docker-compose.faucet.yml logs -f faucet-backend
docker-compose -f docker-compose.faucet.yml logs -f faucet-postgres
docker-compose -f docker-compose.faucet.yml logs -f faucet-redis
```

### Check Faucet Balance

```bash
# Inside container
docker exec aura-validator-1 aurad query bank balances $(cat .env.faucet | grep FAUCET_ADDRESS | cut -d'=' -f2) \
  --chain-id aura-local-4

# Or via API
curl http://localhost:8081/api/v1/faucet/info | jq '.balance'
```

### Refill Faucet (if balance is low)

```bash
# Get faucet address
FAUCET_ADDRESS=$(grep FAUCET_ADDRESS .env.faucet | cut -d'=' -f2)

# Send more tokens from validator-1
docker exec aura-validator-1 bash -c "
  echo 'password123' | aurad tx bank send \
    \$(aurad keys show validator-1 --keyring-backend test --address) \
    ${FAUCET_ADDRESS} \
    50000000000000uaura \
    --chain-id aura-local-4 \
    --keyring-backend test \
    --gas 200000 \
    --gas-prices 0.025uaura \
    --yes
"

# Wait and verify
sleep 6
docker exec aura-validator-1 aurad query bank balances ${FAUCET_ADDRESS} --chain-id aura-local-4
```

### Database Management

```bash
# Connect to PostgreSQL
docker exec -it aura-faucet-db psql -U faucet -d faucet

# View recent requests
SELECT recipient, amount, status, created_at
FROM faucet_requests
ORDER BY created_at DESC
LIMIT 10;

# View statistics
SELECT
  COUNT(*) as total_requests,
  COUNT(DISTINCT recipient) as unique_recipients,
  SUM(CASE WHEN status = 'success' THEN amount ELSE 0 END) as total_distributed
FROM faucet_requests;

# Exit psql
\q
```

### Clear Rate Limits (Emergency)

```bash
# Clear all rate limit data
docker exec aura-faucet-redis redis-cli FLUSHDB

# Verify
docker exec aura-faucet-redis redis-cli DBSIZE
```

### Backup Database

```bash
# Create backup
docker exec aura-faucet-db pg_dump -U faucet faucet > faucet-backup-$(date +%Y%m%d-%H%M%S).sql

# Restore backup
cat faucet-backup-20251210-120000.sql | docker exec -i aura-faucet-db psql -U faucet faucet
```

## Troubleshooting

### Faucet Service Won't Start

**Symptom:** `docker-compose -f docker-compose.faucet.yml up` fails

**Solutions:**

1. Check if testnet network exists:
   ```bash
   docker network ls | grep aura-testnet
   ```
   If missing, start testnet first:
   ```bash
   docker-compose -f docker-compose.testnet.yml up -d
   ```

2. Check if `.env.faucet` exists and is valid:
   ```bash
   cat .env.faucet
   ```
   If missing, run `./scripts/faucet-setup.sh`

3. Check for port conflicts:
   ```bash
   lsof -i :8081  # Faucet backend
   lsof -i :5433  # PostgreSQL
   lsof -i :6380  # Redis
   ```

### Cannot Connect to Validator

**Symptom:** Faucet logs show "connection refused" or "dial tcp" errors

**Solutions:**

1. Verify validator is running:
   ```bash
   docker ps | grep validator-1
   ```

2. Check if faucet backend is on testnet network:
   ```bash
   docker inspect aura-faucet-backend | grep aura-testnet
   ```

3. Test RPC connection from faucet container:
   ```bash
   docker exec aura-faucet-backend wget -qO- http://aura-observer-1:26657/status
   ```

### Transactions Failing

**Symptom:** Faucet requests fail with "insufficient funds" or "account not found"

**Solutions:**

1. Check faucet balance:
   ```bash
   curl http://localhost:8081/api/v1/faucet/info | jq '.balance'
   ```
   If low, refill using the refill command above.

2. Verify mnemonic is correct:
   ```bash
   grep FAUCET_MNEMONIC .env.faucet
   cat testnet-data/faucet/faucet.mnemonic
   ```

3. Check if account exists on chain:
   ```bash
   FAUCET_ADDR=$(grep FAUCET_ADDRESS .env.faucet | cut -d'=' -f2)
   docker exec aura-validator-1 aurad query bank balances ${FAUCET_ADDR} --chain-id aura-local-4
   ```

### Rate Limits Too Strict

**Symptom:** Getting "too many requests" errors during testing

**Solution:** Temporarily relax rate limits or clear Redis:

```bash
# Option 1: Edit .env.faucet and increase limits
vim .env.faucet
# Set FAUCET_RATE_LIMIT_IP=100 and FAUCET_RATE_LIMIT_ADDR=50

# Restart
docker-compose -f docker-compose.faucet.yml restart faucet-backend

# Option 2: Clear rate limit cache
docker exec aura-faucet-redis redis-cli FLUSHDB
```

### Database Connection Errors

**Symptom:** "connection refused" or "database does not exist"

**Solutions:**

1. Check PostgreSQL is healthy:
   ```bash
   docker-compose -f docker-compose.faucet.yml ps faucet-postgres
   ```

2. Verify database exists:
   ```bash
   docker exec aura-faucet-db psql -U faucet -l
   ```

3. Check logs:
   ```bash
   docker-compose -f docker-compose.faucet.yml logs faucet-postgres
   ```

## Production Deployment Considerations

For production/public testnet deployment, consider these enhancements:

### 1. Enable CAPTCHA

```bash
# Sign up for hCaptcha: https://www.hcaptcha.com/
# Get your site key and secret

# Add to .env.faucet
FAUCET_HCAPTCHA_SECRET=your_secret_here

# Update frontend/index.html with site key
# Restart services
```

### 2. Enable HTTPS with Nginx

```bash
# Generate SSL certificates
./scripts/generate-ssl-certs.sh

# Start with production profile
docker-compose -f docker-compose.faucet.yml --profile production --env-file .env.faucet up -d

# Access via:
# https://localhost:8443
```

### 3. Set Stricter Rate Limits

```bash
# Edit .env.faucet
FAUCET_RATE_LIMIT_IP=5
FAUCET_RATE_LIMIT_ADDR=1
FAUCET_RATE_WINDOW=24

# Set production mode
FAUCET_ENVIRONMENT=production
FAUCET_LOG_LEVEL=warn
```

### 4. Use Secure Database Password

```bash
# Generate strong password
SECURE_PASS=$(openssl rand -base64 32)

# Update .env.faucet
FAUCET_DB_PASSWORD=${SECURE_PASS}

# Restart services
docker-compose -f docker-compose.faucet.yml down
docker-compose -f docker-compose.faucet.yml --env-file .env.faucet up -d
```

### 5. Set Up Monitoring

Consider adding:
- Prometheus for metrics
- Grafana for visualization
- Alertmanager for notifications
- Log aggregation (ELK stack)

## Security Best Practices

1. **Never commit `.env.faucet`** - Add to `.gitignore`
2. **Secure the mnemonic** - Store `testnet-data/faucet/faucet.mnemonic` securely
3. **Use firewall rules** - Restrict access to PostgreSQL and Redis ports
4. **Enable CAPTCHA** - For public-facing deployments
5. **Monitor for abuse** - Set up alerts for unusual activity
6. **Regular backups** - Backup PostgreSQL database regularly
7. **Update dependencies** - Keep Docker images and Go modules updated

The AURA testnet faucet provides a professional, production-ready solution for distributing test tokens. It features comprehensive rate limiting, request tracking, and monitoring capabilities.
